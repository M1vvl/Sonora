# Sonara 工程与维护要求

2026-10-28，用户提出的长期要求原文：

> 同时我现在需要强调一点，对于当前这个Agent Pulse，我希望可以让功能模块化一些，以减轻后期的维护修改完善，以及降低整个软件的运行时的运行内存和提高软件的运行效率与逻辑运行效率，降低bug出现的可能性，降低以后的维护成本，

## 生命周期与资源

- 创建者负责释放：子进程、音频客户端、COM 对象、定时器、监听与动画循环必须有停止路径。
- 音频只在可见灵动岛开启律动时运行；隐藏、关闭律动或退出应用后停止 helper。标准输入管道关闭后 helper 自行退出，防止主进程意外退出后的孤儿采集。
- 默认自动识别活跃输出音频会话。没有音频会话时约每秒检查一次，不开持续回环；有声音时频谱最多约 20 帧/秒，UI 最多约 30 帧/秒，只更新 `transform`。
- 不为了三个条形引入第二个 Electron 运行时、WebGL 场景或额外浏览器窗口。音频 PCM 仅短时保存在有界缓冲区中，输出仅三个数值和有限状态。
- 仅灵动岛启动时不创建主面板。2026-11-06用户要求关闭面板后保留音乐，存在当前音频或待完成取流时保留拥有audio的原renderer并隐藏、停止视觉工作，无音乐时仍释放面板，完全退出停止音乐。托盘仍可重新打开。
- 不向隐藏窗口发送完整历史；灵动岛只接收主会话摘要和最新活动。音频使用独立小消息，不触发用量快照或托盘菜单重建。
- 用户要求真实边缘折射同时在录屏中可见。不得启用内容保护或截图排除；只从严格位于岛轮廓外的像素取样，四个双线性邻点都要通过安全域校验。采样仅在内存中处理，最多 4 帧/秒，隐藏或关闭后释放 GDI 资源；尺寸过期帧不得拉伸显示。诊断截图使用合成背景输入，不记录真实桌面像素。

## 正确性与故障隔离

- 统计结果正确优先于“看起来更快”；保持归档、去重、缓存基线和北京时间划日测试。
- 新功能可独立关闭。音频设备不可用、helper 缺失或退出时静态显示，监控与计价继续工作。
- 子进程只允许固定路径和枚举参数；协议验证后使用，缓冲有大小上限，异常退出有限退避，避免重启风暴。
- 音频默认分析默认输出设备的混合声音，不把它称为独占某一播放器。其他设备、受保护/独占音频等限制要诚实记录。
- UI 模块尊重减少动态效果：保留低频的离散音频表头反馈，关闭插值与动画循环；不使用随机数或固定 keyframes 冒充真实音频。
- 音乐沉浸页的歌词播放进度属于语义状态：减少动态效果时也要按 10fps 更新真实歌词/频谱，弱化运动；不得把语义更新与鼠标移动绑定。标准预设共用宿主；跨渲染器切换只有新场景完成实际绘制后才释放旧画面，转场最多两个宿主，隐藏/关闭全部释放。
- 每张用户配色参考图对应一套完整主题；三色必须分工呈现在基底、导航和重点卡片等真实区域，不能拆成单色主题或只在缩略色板里列出。强色块的文字单独校验对比度。
- 2026-10-29 用户强调：排版改动不授权切换主题或修改配色。预览应使用正式配置中的主题；测试配置、截图和正式用户目录严格分离。保存后的主题与其他偏好应在完全退出、重启后恢复，不将诊断默认主题写回正式配置。
- 关闭面板和完全退出均应保留最后工作区：项目/子代理展开、选中会话、搜索/Agent 筛选、统计范围/日期、明细展开、热图模式与滚动位置。面板状态独立于主题设置和历史用量存储；使用 180ms 单次合并保存，退出时同步补齐未提交的操作。初始日志索引未完成时不得用临时默认会话覆盖保存的选择；搜索自动展开不得覆盖原折叠偏好。“今日”跨天保持动态，不冻结为上次启动日期。
- 面板非交互内容默认左键拖动窗口；文字须先真实字形悬停再水平拖动选择。保留表单、按钮和触屏原行为。实时快照不得重建正在阅读或选择的消息 DOM，其他统计继续更新；手势仲裁与阅读状态由独立模块维护。

## 验证与维护

- 根据修改运行相关单元检查、原生 FFT 自检、真实音频探测和成品冒烟；不为简单改字增加镜像实现的测试。
- 衡量 CPU、内存、IPC 体积时记录版本、场景与采样时间，不凭架构图承诺减少百分比。
- 音频供应方、协议、渲染策略分别扩展。以后增加应用独立回环、频带数或设置，不应修改 Token 计价和日志解析模块。
- 每次发布同步 README、版本和构建步骤。保留真实限制和未验证项，禁止把 API 返回成功写成视觉或性能通过。
- 番剧页首次显示时才创建服务；规则 HTML 解析器进一步按需加载。元数据、图片和规则请求共用最多 4 个并发；来源搜索同时最多 3 个。图片 LRU 缓存限制 24MiB/60 项，观看历史限制 100 项，ECH 工作线程空闲 60 秒释放。关闭页面取消排队及活跃请求，退出应用先完成原生回调取消再退出。
- 播放控件是主窗口中的独立沙箱 WebContentsView，只暴露播放桥；Windows 原生视频子 HWND 只占视频区域。菜单通过收缩该区域露出，不能依靠 HTML 覆盖原生 HWND。远程解析窗口不加载 preload、不使用 Node、不获监控日志权限。进度来自真实播放状态，点击条目和解析失败不能生成观看历史。
- 原生组件只在播放时启动，回退/返回/切换导航/退出释放；标准输入关闭后自行退出，停止超过 2.5 秒终止该 helper。协议请求最多 32 个，字段、命令及着色器目录校验后才执行；4Hz 状态不发送全集列表、不重建播放器或用量索引。
- 尺寸同步优先合并到动画帧，另设一次性 50ms 兜底，兼容遮挡或隐藏时不提交帧的视图；两者在上报或销毁时一起取消，不创建持续布局轮询。设置提交后再次核对播放代次，防止切集/返回后的旧操作影响新视频。产品不提供保存视频截图；只有显式诊断启动的 helper 才允许内部验证帧写入。
- 2026-10-30：软件分发给其他用户时不应依赖开发者本地的 Kazumi、LibreTV 源码、Docker、Node.js 或开发工具。随包提供原生组件和默认规则/源；使用全新独立用户目录验证，不能把本机可用等同于所有 Windows/网络永久可用。影视共用番剧 UI 和播放器，服务在首次进入时创建；网络并发上限 4、单源任务上限 10 秒，瞬时网络失败最多重试一次。连续失败暂时退避，到期按请求恢复；不增加持续探活轮询。四个默认非成人影视源保留官方历史配置出处，不声称第三方视频源永远在线。
- 音乐登录、目录、账号偏好/历史、图片、音频流与 UI 分责，首次进入时加载。封面最多 4 个活跃请求、64 个等待请求，单图 2MiB、缓存总计 8MiB/64项，排队取消和退出均释放；音频仅保留当前歌曲的不透明协议地址，以背压流式转发，不缓存整曲。三张卡片共用单个 WebGL 上下文，画布最大 384×384、CDN缩略图384px、封面纹理最大 512×512、环境模糊缓冲 256×256；仅在实际手势与回弹时调度帧，隐藏释放 GPU。最近播放小更新不得重建推荐列表或传给监控索引。
