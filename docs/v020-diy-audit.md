## 模块与资源审查

- 主进程 `src/music-visual/` 只处理本地媒体、受控协议、Steam/原生窗口、内存状态。renderer 不获得任意本地路径、Shell 或 Node 权限。
- 本地协议校验 realpath 后仍须在项目根内；资源大小、MIME、range、流数量均受限。网页壁纸使用无同源权限的 sandbox iframe，禁止远程连接、摄像头、麦克风和子帧；只有带项目 token 的父消息被桥接。
- 捕获权限仅在短时租约有效、当前主面板 webContents 和 mainFrame 匹配、窗口句柄/进程/签名引擎路径匹配时授予，且不包含音频轨。没有授予全桌面或其他应用窗口的通用捕获权限。
- 共享 `audio-analysis.js` 以当前 audio 为 WeakMap 键建立唯一 MediaElementSource/AudioContext；消费者引用计数释放，歌词小卡、沉浸预设和网页壁纸复用频谱。没有再建播放器，没有下载整首歌曲做节拍缓存。
- 进入沉浸页时底层封面卡与小歌词卡停止并删除 GPU 对象；回到主页按需恢复。沉浸渲染器上限 960×540，几何缓存低于 4MiB；小歌词材质画布上限 256×384，只有三张纹理和两个模糊缓冲。
- 全部计时器、RAF、observer、监听、捕获轨和自有场景都有关闭/销毁路径。原生窗口生命周期不等于浏览器 video 元素的 pause，发布前必须分别核查。
- 视觉设置只作用于沉浸界面；不改正式主题配置，也不改 Windows 全局透明设置。

## 审计发现与发布前核查

独立读取实现时发现以下具体问题。主实现者已完成修复，随后逐项只读复核了修复后的源代码；实际运行结果仍由综合门禁和成品门禁另行记录：

1. **背景参数：已修。** 共同的透明度、模糊、缩放、变换原点与媒体定位在 `studio.applyBackground()` 之前应用，不再被自选媒体的提前返回跳过。
2. **三维歌词：已修。** HTML 与 CSS 均使用 `data-lyric-3d`，当前行的 `translateZ` 和景深参数命中同一控制路径。
3. **歌单架错源：已修。** `loadSongs()` 只返回本次成功取得的歌曲快照；失败、取消和 busy 返回空值。播放回调同时校验当前选中歌单 ID，不读取上一歌单的残留数组。
4. **WE combo 类型：已修。** 按描述符选项找回原始 value 类型后提交，数字不再被 DOM 字符串替换。
5. **显式保存：已修。** 公共属性捕获项目 ID 与数值快照，内存偏好也合并到独立队列；“保存”先等待 `flushPreferences()` 再等待视觉标量落盘。关闭/销毁补交待提交设置，保存期间又有新编辑时仍显示“待保存”。
6. **原生后台资源：已修。** 隐藏时移除网页 iframe 的 src、停止频谱消息、停止捕获轨并请求关闭自有场景；返回时重新读取项目状态再恢复。启动中的场景同样发送停止请求，后端代次取消不再等待完整窗口轮询；前端 ticket 拒绝迟到的启动/捕获结果。
7. **颜色回显：复核追加并已修。** 主进程的原生 RGB triplet 返回后，经 `publicProperty()` 转回公开 HEX，面板不会把已保存颜色误显示为白色。

本次复核没有修改运行时代码，也未发现新的严重阻塞项。对失败路径的补丁不能单靠静态核查宣称已经运行验证；综合门禁应包括真实计算样式和对应控制结果。
