## 灵动岛：CSS 层叠的关键结论

同一个 `/island.css` 中存在几代玻璃配方。只读到文件前半段会得出错误结论；应以末尾层叠结果为准。

早期 Horizon 材质声明为深色渐变，透明度约 0.26 到 0.48，配合 `blur(3px) saturate(1.25) brightness(1.02)`。授权提示状态还有透明度约 0.30 到 0.44，以及 `blur(22px) saturate(1.5) brightness(0.5)`。

但文件最终的高优先级规则明确将 `body.island-mode`、Horizon body 与 `#islandRoot` 背景设为 `transparent !important`，并把 backdrop-filter 设为 `none !important`。更后面的通配规则又对所有元素及伪元素禁用 backdrop-filter。上述早期 blur 声明在最终 CSS 中不生效。

最终边缘仍保留这些可验证视觉参数：

- 内顶部高光约 58% 白色，1px。
- 内圈 1.5px 软高光，约 32% 白色。
- 底部浅内光约 12% 白色。
- 外部 1px 轮廓约 15% 白色。
- 外阴影约 42% 黑色、14px 下移、40px 模糊。
- 文本使用多层黑色微阴影，增强复杂桌面背景上的辨识。
- 收起胶囊高 44px、圆角 22px；图标 15px；动作文字约 11px/650；有动作时 Agent 名退为 9px 次级文字。

因此，**已观察到的当前前端更接近“全透明清玻璃 + 亮边 + 文字阴影”，不是已经证明的跨桌面磨砂玻璃。** 资源中的注释解释了为何移除 blur，但注释本身并不是 Windows 运行时证据。用户希望实现磨砂玻璃，可以独立做得更完整，无需照搬已被覆盖的 Terse CSS。

## Windows 原生模糊：证据边界

对二进制的定向字符串检索有如下命中：

| 内容 | 文件偏移 | 能证明什么 |
| --- | ---: | --- |
| `apply_blur()` 系统版本提示 | `0x297ce61` | 制品包含相应原生材质库的代码/错误信息 |
| `apply_acrylic()` 系统版本提示 | `0x297cfb5` | 存在 Acrylic 相关实现组件 |
| `SetWindowCompositionAttribute` | `0x297d063` | 包含动态 Windows 合成调用符号 |
| `DwmSetWindowAttribute` | `0x2ed7828` | PE 存在 DWM 窗口属性调用符号 |
| `DwmEnableBlurBehindWindow` | `0x2ed7baa` | PE 存在 DWM 背景模糊调用符号 |

这些库提示和导入符号不能证明 `island` 窗口实际走了哪个调用，更不能证明其参数、区域裁剪和成功返回值。本轮没有注入目标或拦截调用，不能声称已恢复完整原生材质链路。

对于 Agent Pulse 的 Electron 45，官方提供 `setBackgroundMaterial('acrylic')`，由 DWM 绘制系统背景材质，支持 Windows 11 22H2 及更新版；`mica` 更适合长驻窗口，`acrylic` 对应暂态窗口。这里是官方能力说明，不保证与透明胶囊、自定义区域或所有显卡组合都兼容，必须在本机视觉验证。[Electron BrowserWindow 官方文档](https://www.electronjs.org/docs/latest/api/browser-window#winsetbackgroundmaterialmaterial-windows)

原生材质应用到整个 HWND，若透明窗口内还留 10px CSS 阴影空白，可能出现矩形磨砂外框。应确保模糊区域、窗口圆角/裁剪区域和可视胶囊同步，并覆盖展开、收起、缩放、拖动后的区域。CSS 的 backdrop-filter 只能提供渲染器内部层的效果，不能独立充当跨窗口桌面模糊的已验证方案。

## Agent Pulse 独立设计建议

本轮读取并应用 Apple Design 的材质、排版、直接操作与辅助功能原则，来源为 `C:\Users\10707\.codex\skills\apple design skill\skills\apple-design\SKILL.md`。界面应优先让费用可读，玻璃用于表达悬浮层级。

事件卡片可采用自主机器人/齿轮图形，18px 图标配 24px 图标栏；助手左侧紫色、工具左侧酸橙绿，均为 3px 角色边框。标题 13px/650，正文 12px/1.55；保持圆角约 18–22px。Token 与 USD 放到第一行右侧，Token 13px、金额 15px/700，金额采用高对比酸橙绿。窄窗口允许独立指标行，避免挤掉标题。所有数字使用等宽数字，避免更新时跳动。零金额保持三位小数，小额非零可四位，未知单价明确保留未定价。

历史和今日应由数据层独立汇总，再在会话和项目的同一位置显示明确标签。项目树的父层显示完整历史汇总，子层显示对话标题；每日统计不应混用会话 lifetime 累计。子代理默认折叠在主对话下，避免一屏零用量代理淹没真实对话。

灵动岛可采用无彩色的薄玻璃表面、顶部高光、细内边和单层柔和阴影；文字/金额采用接近白色和明亮酸橙绿，而非透明灰字。真实磨砂优先用 Windows 原生 Acrylic，网页层只增加约 12%–28% 深色 tint 与边缘照明，避免高 alpha 把玻璃重新变成黑色块。展开面可稍提高 tint 维持正文可读性。

需要同时提供减少透明度和高对比降级：接到对应偏好时改用接近实色的深底与清晰边框；拖动应一比一跟随，不在每次 Token 更新时重播动画。尺寸/状态变更可用 160–220ms 的 opacity / transform 过渡，并支持 reduced motion。

## 验收要点

1. 事件卡片图标、角色名、Token 与金额在 100% 系统缩放下直接可读；金额不再位于极小的右下角。
2. 文本缺失逐消息用量时不伪造 0 Token 的精确计费，模型请求成本仍可由真实 usage 行显示。
3. 暗色、明亮和复杂背景下都看得到桌面色彩变化，Acrylic 模式下背景细节确实被模糊，而不只是整体降低不透明度。
4. 收起/展开后无矩形磨砂残留，拖动后无残影或裁剪位置错误。
5. 项目完整历史、对话完整历史与今日三个数可以分别复核；没有默默限 120 文件或截尾 32MiB 却标为完整历史。
6. 界面不显示 Plus 订阅费。以模型官方单价的 Token 美元估算为中心，未定价/信息缺失保持可辨。

## 全历史验收中的真实数据校正

全历史扫描另发现两个以前短尾扫描没有暴露的问题，均由本机原始日志确认，而非模拟猜测：

- 174 个现存文件中，129 个文件包含两个不同的 `session_meta`。第一条属于当前子代理，第二条重放父对话元数据。若每遇到元数据就覆盖身份，会把子代理混入主对话、覆盖角色，并漏掉后续属于子代理 ID 的真实 usage。文件/索引与首条有效元数据应确定稳定身份，后续重放只能视为上下文。
- 部分旧会话在累计使用后才开始写新版 `token_usage_record`，它的 `thread_token_usage` 从零开始，旧 `token_count` 却保留完整历史基数。一个真实文件在旧累计 `745,416,590` 后写入新版请求 `193,794`，新版线程累计为 `193,794`，随后旧累计为 `745,610,384`。两个累计的固定偏移不能重复收费。现改为独立保留旧累计基线，用新版真实请求增量记账，并从下一次旧累计增量中扣除已记的新请求。

独立读取该 109,537,052 字节真实文件后，最终历史 Token 为 `762,576,982`，与其最后一条旧累计精确一致；今日为 0，无截断或解析错误。新增四个累计基线回归覆盖固定偏移、缓存/输出/推理、重启缓存间的待镜像请求，以及重复请求的扣减；全套 30 项测试通过。

会话数量也独立核对过：174 个本地文件对应 173 个不同 ID，其中 163 个明确同时带子代理 source 对象及 `thread_source=subagent`，10 个为主对话；并不存在仅因 `agent_path` 字段误判主对话的情况。SQLite 还留有 12 个已归档主对话索引，但其日志文件已不存在。完整历史的承诺因此限于“本机现存且可读的日志”，无法凭索引补造已删除会话的 Token 明细。
