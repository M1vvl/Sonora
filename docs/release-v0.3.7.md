## REA 证据

使用已缓存的 REA 6.8.0 CLI 对用户指定的 Windows 安装目录做只读观察：

- `artifacts/kazumi-rea/desktop-evidence.json`：76 个目录条目，有限文件头观察。此版本识别器没有报告 Flutter 候选，不能据此推断不是 Flutter。
- `artifacts/kazumi-rea/ech-exports-evidence.json`：原装 `ech_http.dll` 为 amd64 PE，共六个导出，SHA-256 `f53e1ae77086bb745697e5f32245d39d7b44edd872007b59a0d9732a6e9c18f9`。
- 功能语义来自用户提供的 `Kazumi-main/Kazumi-main/lib` Windows 实现；原程序和用户配置不写入、不修改。

## 原始数据与边界

本机 Kazumi 的规则文件位于 `%APPDATA%/com.example/kazumi/plugins/v2/plugins.json`，首次导入到 Agent Pulse 独立数据目录，之后分别管理。番剧播放源属于第三方网站，个别站点停服、验证或资源失效时显示具体原因，可切换其他规则，不声称每个来源永久可用。

热门列表来自 Kazumi 的镜像热门接口，五个精选按该候选集中的真实评分排序。Bangumi 没有提供各第三方播放站的总播放量，界面不伪造“最高播放量”，显示真实评分和排名。镜像详情使用源码中的 `/p1/subjects/{id}`；不能将旧 `/v0` 路径直接拼到镜像域名。

## 封面适配核对

对照 `lib/bean/card/network_img_layer.dart`、`lib/services/network/image_acceleration.dart`、`lib/request/core/ech_transport.dart` 和 `lib/utils/image_extension.dart`：保留条目封面 URL，使用 HTTP(S) → 独立受控图片协议 → 加速模式 → 原装 ECH 库的通路。图片镜像仍按 Kazumi 的 wsrv.nl 规则改写，GIF 参数保留。图片在内存 LRU 中缓存；失败回退占位，成功加载显式恢复图像显示。

初次预览截图采到了隐藏窗口尚未提交的占位画面；只检查 `naturalWidth` 不足以证明最终画面。诊断现同时核对实际图像加载、未隐藏、五张图片数量，等待绘制并丢弃过期合成帧，然后保存截图供人工查看。最终截图必须看到对应封面，不能把占位渐变当作封面验收。

## Windows 核心保留与适配

规则的原始选择器、请求方法、JSONPath、API 模板、线路与集数顺序保留；HTML 在独立无脚本 DOM 中解析。来源搜索最多三路并行，每个来源完成就展示，可取消；单站错误不阻断其他站点。规则管理、仓库更新、网络选项与观看历史分别维护。

Windows Flutter WebView2 + libmpv 的宿主层适配为隔离的 Chromium 解析窗口和 HTML5/HLS 播放器，没有嵌入其他平台工程。远程页面不接触监控桥。已用真实规则返回的 MP4 和普通网页媒体请求验证播放/进度/释放；不承诺原 libmpv 支持的所有冷门编码，也不移植移动端功能。保留本机 Kazumi 打开入口用于来源兼容性回退。

镜像的签名搜索需要发行版未公开的构建凭据，因此关键词搜索使用 Bangumi 官方公开接口并启用 ECH，不提取或复用其私有签名凭据。热门、分类及详情继续默认镜像。界面说明此差异，不将公开接口称为受签名镜像搜索。

## 验证入口

- `npm test`：规则模板、XPath/API 语义、取消/并发、UI 异步竞争、错误来源隔离、原生回调字节复制及其他既有回归。
- `node scripts/check-anime-network.cjs`：真实热门、详情、分类、关键词、封面、仓库及分集地址；ECH 必须由原生返回确认。
- `scripts/check-anime-player.cjs`：独立隐藏静音 Electron 实例检查真实视频、进度、网页媒体解析及释放，不写入用户观看历史。
- `npm run release`：构建成品后重复面板、灵动岛、真实封面、导航及设置检查，再替换运行版本。
