# 0.3.21 音乐账号恢复

## 原因和修复

已保存的网易云凭据原先在启动校验遇到临时网络错误时，虽然文件还在，界面却发布了未登录状态；部分 HTTP 200 但没有完整 profile 的响应也会触发清除。这让正常保存看起来像失效。

现在把验证结果区分为 `pending / verified / invalid`。暂时离线、上游错误或缺少 profile 时保留加密凭据与上次账号资料，显示“已保存 · 待核实”。按需重试有 30 秒间隔，没有常驻登录轮询。只有明确的失效响应（301/302/401）才清除；平台轮换的 cookie 重新加密写入。Windows safeStorage 暂不可用时也不删除旧文件。

登录浮层放在独立 portal 中。对应 SVG 连线、隐藏区域和按钮样式现在以 `.music-account-root` 为作用域，修复进入沉浸页后出现大块空白的问题。浮层打开时暂停背后场景交互；关闭后恢复同一播放器和页面。

## 验证边界

- 账号单元测试使用合成凭据，覆盖离线、失效、资料缺失、轮换和加密失败。
- `scripts/check-music-auth-restart.cjs` 在四个独立 Electron 进程中使用真实 Windows safeStorage 验证保存、离线启动、轮换和再启动；资料与凭据全部是隔离生成的测试值。
- `scripts/check-music-v021.cjs` 使用正式 dashboard 与 preload 核对待验证账号显示、一级/沉浸页的浮层、连线和尺寸。
- 不读取其他播放器的登录 cookie，不把真实用户凭据写入诊断报告；这些检查不能保证服务端永远不使登录失效。用户主动退出或平台撤销授权后仍需要登录。

Apple Music、Spotify 等其他入口的当前范围和原因见 `v021-platform-integration.md`。本轮没有用仅打开登录网页的方式冒充歌单及播放已完整接通。
