# 0.3.0 音频律动与模块拆分验证

日期：2026-10-28。

## 已交付行为

默认 `musicReactive=true`、`audioSourceMode=auto`。启动灵动岛即自动识别默认输出设备上的活跃音频，用户无需选择播放器。保留关闭开关与“仅常见音乐播放器”模式。低、中、高频条形由实际输出数据驱动，静音后回落；自动跟随输出设备切换。

本机同时启用了减少动态效果，因此用最多 10Hz 的离散条形显示功能性音频数据，不启用插值动画；正常动效模式最多约 30Hz 绘制。没有改 Windows 透明效果或动画设置。

## 模块拆分

- 新建 `native/audio`：WASAPI 会话发现、输出回环、2048 点 Hann 窗 FFT、三频带能量与释放包络。
- 新建 `src/audio`：独立小 helper 生命周期、输入验证、长度上限、有限重启退避。
- 新建 `ui/audio-visualizer.js`：只更新三根条形的 transform，不触发历史索引或页面重绘函数。
- 新建 `src/snapshots.cjs`：灵动岛摘要协议，只保留主会话和最新活动。
- 将完整冒烟诊断从主进程入口移到 `src/diagnostics/smoke.cjs`。
- 主面板按需创建；关闭释放，托盘仍可恢复。隐藏岛、关闭律动、退出时停止 helper，标准输入断开时 helper 自行退出。

长期维护约束记录在 [engineering-principles.md](engineering-principles.md)，项目 `AGENTS.md` 要求后续修改遵守这些边界。

## 已完成检查

- 37 项 Node 单元测试通过：原有统计/历史/身份测试、音频协议与生命周期、静音停止动画循环、减少动效功能反馈、摘要投影等。
- 原生自检通过：100Hz、800Hz、5000Hz 分别落入三个频带；无输入后回落到零。测试不播放音频。
- Electron 成品 28 项检查通过：设置、自动默认值、手动覆盖、音频帧桥接、透明通道、直接点击展开、会话切换、计价和日历史区分。renderer errors=0。
- 本机真实 WASAPI 诊断自动识别 `cloudmusic`。4 秒采样的三带值均有变化，实测消息约 15.6 帧/秒，低于 20Hz 上限。原始音频没有持久化。详见 `artifacts/v0.3.0/audio-live-report.json`。

## 资源观测

176 个会话的一次实际快照：完整数据 4,433,494 字节，岛摘要 15,311 字节。音乐帧单独发送，只包含三带值、有限状态和来源名称，避免每次律动复制约 4.4MB 的会话数据。此测量是这个数据集的一次样本，不承诺所有数据集相同比例。

播放时 helper 的短时工作集样本约 26–27MiB，私有内存约 9MiB。整个应用旧版与新版的点时样本分别约 880MiB 与 476MiB（新版包含 helper）；两次采样的应用运行时长不同，不构成严格对照基准，不能视为固定节省比例。原始点时记录保留在 `artifacts/v0.3.0/*process-memory.json`。

## 能力边界

这三个柱形是实时频带能量显示，不是精确 BPM 或音乐语义分析。默认输出的其他声音会混合进入；“仅常见音乐播放器”也只改变活跃来源门控，不隔离混音。非默认设备、独占模式、受保护内容和某些驱动可能无法响应。网易云已真实验证；QQ 音乐和 Mineradio 未逐个启动实测。

Mineradio 的定向 REA、静态证据范围与一手调研见 [mineradio-audio-analysis.md](mineradio-audio-analysis.md)。未复制其代码和资源到产品。
