# v0.3.21 播放会话恢复独立审查

审查日期：2026-11-02。仅使用合成歌曲、合成 IPC 和临时目录；没有读取真实账号凭据、收藏或歌单，没有调用番剧/影视测试。

## 保存范围与内存含义

`src/music/playback-state.cjs` 是独立的本地元数据仓库，文件为应用数据目录下的 `music-playback.json`。只保存当前歌曲的 ID/名称/歌手/专辑/封面引用/时长/喜欢状态、队列顺序、进度秒数、顺序/单曲/随机模式、音量和静音。队列最多 1,000 首，整个 JSON 最多 512 KiB；重复 ID 去重，保持第一次出现的顺序。原子临时文件写入后替换正式文件，临时文件在成功或失败后清理。

保存进度需要少量磁盘元数据；这不是音频缓存。音频文件、完整响应、PCM、Cookie、登录凭据、签名音频地址、`pulse-music-audio` 临时令牌和任意附加字段均不进入该 JSON。歌曲数据重新经过已有 `catalog.song` 白名单归一化，封面仅接受既有网易云图片 CDN 的引用。

音乐通过 `src/music-stream.cjs` 流式播放，使用不持久化的 Electron 网络分区和 `no-store` 请求/响应；该模块没有文件写入，也不缓存完整歌曲。播放、网络传输和解码仍必须使用临时 RAM 缓冲，无法让计算机在零内存条件下播放音乐。断网时现有流程移除音频源、清空媒体缓冲并停止流；退出进程后临时音频缓冲释放。再次播放仍须联网重新获取音频。

## 恢复与退出的时序

1. 新播放器通过本地 `playbackState` IPC 读取元数据；这个 IPC 位于音乐账号/网络服务初始化之前，不会初始化网络分区、请求播放地址或创建音频流。
2. `player.restorePlayback` 恢复当前歌、队列、模式、音量、静音和进度，保持暂停状态；音频元素没有 `src`，不会自动播放。
3. 用户点击播放后，才重新请求当前歌曲的临时受控播放地址。媒体信息就绪后，再应用保存的进度；旧的签名地址不用于恢复。
4. 页面离开、`beforeunload`、模块销毁均先 flush。退出采用 preload 的同步 IPC，将最后进度写入后才允许播放器销毁清空媒体。主进程退出流程还有显式 `flushPlayback` 收尾。
5. 正常播放时间最多每 5 秒触发一次后台保存；队列、模式和元数据变化按 180 ms 合并。退出同步 flush 不等待该延迟。
6. 如果初始读取尚未完成，后续用户编辑的队列优先；迟到读取不能覆盖。未修改的空播放器被动渲染不阻止恢复。读取过程中销毁不会用默认空状态擦掉原记录。

“恢复不联网”限定为恢复播放会话本身不获取音频。完整音乐主页仍可按既有流程加载推荐、封面、歌词或校验账号；不声称整个音乐界面完全没有网络请求。

## 独立审查发现及修复

- 恢复音量后，实际音频音量正确但滑杆仍停在默认值：音量渲染统一读取真实音频音量，同步状态与滑杆。
- 暂停恢复且尚无音频源时，进度拖动被旧位置覆盖：改为只更新待恢复秒数，不取流、不启动播放，点击后再应用。
- 初始读取较慢时，被动 `time`/空播放器重绘误判为用户编辑：只让有歌曲的时间变化和实际语义事件更新恢复竞争序号。
- 非对象输入或无当前歌的残留位置：归一化为安全空状态；无歌的位置固定为零。
- 恢复暂停时歌词元数据稍后到达，零值 `audio.currentTime` 覆盖已恢复的游标：歌词管理器和共享投影统一在音频尚无 `src` 时保留外部传入的恢复位置；开始真实播放后再跟随媒体时钟。设置变更、暂时遮挡、暂停和重进页面也不跳回开头。
- 歌单详情确认喜欢状态后，当前播放条可能显示旧状态：新增 `player.applyLiked(id, liked)`，复用既有队列对象和音频，仅同步当前歌/队列并发出 `metadata`；不重建队列，因此不丢失正在使用的随机播放集合。
