# 影视十卡惯性与拖动卡顿修复

此修复纳入0.3.19统一发布；用户随后明确要求全部完成后打包替换0.3.18。

## 已定位原因

1. 原 `pointermove` 每个事件直接写 `scrollLeft`。高轮询率鼠标在同一显示帧内可触发多次滚动提交；改为保存最新目标，只排一个requestAnimationFrame，释放时补齐最后目标。
2. 卡片仍继承主面板 `button:active` 的缩放过渡，且图片原生拖拽没有在影视轨道禁用。原生drag与自定义横滑可能竞争并取消指针；现在阻止轨道dragstart、图片user-drag，并取消影视卡片按下缩放。
3. 旧释放速度上限2.5px/ms、短衰减使实际移动通常仅一两卡，即使只改预算到10也无法实现长滑。现在使用经过输入平滑的释放速度投影，目标限制在手势起点±10卡步长，并以到零速度的ease-out结束；速度越快，投影越远，慢拖不强制跨10卡。

## 资源和准确性

- 只在pointerdown读取两张卡的真实宽度和间距。pointermove不测量布局；一个输入批次只留一个待帧。
- 电影明确传`maxTravelCards:10`；共享模块默认仍2，音乐歌单保留原合理范围。
- 直接拖动和释放惯性共享十卡预算，页面剩余不足时以真实边界为准。该预算为相对手势起点的净位移，不是反复往返累计路径。
- 按下立即停止惯性，取消/隐藏/失焦/停用/销毁释放帧和捕获；开启减少动态效果时直接结束拖动，不启动惯性。
- 滚动通知按实际位置去重；电影滚动只检查是否接近末尾，封面全量refresh仅在追加新条目时调用，旧卡节点不重建。
- 仍使用原生scrollLeft以保留浏览器滚动、触控、键盘、懒加载与可访问语义，没有另建DOM镜像、WebGL场景或常驻动画。

## 验证

`tests/horizontal-scroll.test.cjs` 7项、电影轨道2项、电影UI7项，共16项相关检查通过。

新增 `scripts/check-movie-motion.cjs`：隐藏真实Chromium、60张合成卡片、独立profile，15项检查通过。80个连续pointermove在同一帧前产生0次scrollLeft写入和0次几何读取，提交帧后只有1次滚动写入。快速滑动实测由4500到6298像素，真实步长179.75px，十卡预算1797.5px（浏览器原生滚动舍入误差0.5px）；释放后继续移动并减速，到目标停止。再次按下立刻停止，旧卡保留，关闭释放且零renderer错误。

报告：`artifacts/hotfix-movie-motion/movie-motion-report.json`。截图为合成诊断，不含用户播放记录或真实桌面。测试证明输入合并和预算/生命周期行为，不承诺任意显卡/刷新率上固定帧率；默认系统减少动态效果时没有惯性，诊断仅对自身renderer模拟正常动态效果，没有修改Windows设置。
