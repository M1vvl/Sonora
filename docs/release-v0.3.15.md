# 0.3.15 分类、真实画质与全屏键盘

## 需求逐项核对

- [x] 影视电视剧/动作/喜剧等具体分类优先查询来源真实分类目录，识别父子类型与别名；每个子分类独立页码，不以推荐空列表判断分类没有作品。
- [x] 番剧科幻/冒险/运动/音乐在镜像未覆盖标签时使用准确的 Bangumi 官方标签，并在后续页沿用同一来源与原始游标；不混入无关热门条目。
- [x] 真实网络验证：四个番剧分类各第一页与下一页、十个影视分类各第一页与下一页均有条目。见 `category-fix-v0.3.15.md` 与 `artifacts/v0.3.15-categories/category-network.json`。
- [x] 番剧与影视共用 GPU 输出：1080p（1920×1080）、2K/1440p（2560×1440）、4K/2160p（3840×2160）目标框，保持原比例。真实中间纹理与 CNN 执行经过 GPU 回读验证，不只是改菜单名称。
- [x] 片源解码尺寸与超分输出目标分开显示。默认质量增强和 4K 目标；无新输出配置的旧偏好首次迁移，之后的明确手动设置保留。输出目标不是把原始片源变成原生 4K，也不改变屏幕实际像素数。
- [x] Esc 退出全屏覆盖 DOM 控件焦点、原生 HWND 与 Electron 输入兜底；幂等退出避免双次事件反而重新进入全屏。窗口模式按 Esc 不退出软件。
- [x] 新增极速与魔都两个 HTTPS 来源；默认源从 4 个增至 6 个，升级只加入新源，不覆盖用户 URL、开关、历史或恢复已删除旧源。
- [x] 影视来源可检测样本画质：HLS `RESOLUTION`、H.264 SPS 或 MP4 编码头。没有可靠像素信息时保持待实测，不凭来源名、片名“4K”或高码率猜测。
- [x] 画质请求沿用共享的 4 并发池，最多读取 64KiB 清单/初始化头、96KiB 分片、16B AES key，12 秒总限时，缓存有界，可取消与释放；不整部下载视频或后台轮询。
- [x] 加密清单隐式 IV 与广告删除序号存在冲突时保守透传，避免破坏原本可播放的视频。
- [x] 268 项单元检查、151 项成品交互检查、13 项面板重启检查及 26 项影视成品检查通过；已打包替换运行，只保留 0.3.15 与 0.3.14 两版便携包。

## 画质与来源证据

`player-quality-v0.3.15.md` 记录 GPU 处理路径、27 个仅修改条件元数据的派生文件、三个独立输出尺寸着色器与 Esc 验证。九个原装 Anime4K 文件、网络系数与原许可保持不变。

`providers-quality-v0.3.15.md` 记录 LibreTV 画质模块 REA、20 个历史来源的实际 API→清单→分片探测，以及“4K”关键词结果的像素核对。新增来源验证通过，但本次样本没有确认到原生 3840×2160 视频；1920×752/756 等电影宽幅尺寸直接显示，不错误地称为原生 4K 或只按短边归为 720p。网络测量是一次采样，不能保证来源永久在线或零卡顿。

本次未修改用户主题、监控计价或 Windows 全局透明设置。新旧功能依然无需额外安装 Kazumi、LibreTV、Docker 或 Node.js；所有原生/派生资源随便携包提供。
