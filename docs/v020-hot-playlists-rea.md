# 热门歌单随机抽取与缓存边界（0.3.20）

## 原因与修改

0.3.19把固定第一页50个热门歌单按播放量排序后取前18，且整个home结果缓存，因此每次看到相似顺序。0.3.20将热门歌单候选与每日歌曲缓存分开：

- `src/music/hot-playlists.cjs`只保留最多150条歌单元数据，按官方hot接口读取0/50/100三页，每页50，五分钟内复用候选；没有后台轮询，不下载歌单歌曲或音频。
- 每次进入音乐主页、显式刷新时抽取18个不同ID，优先避开上一次18个；同一次访问中的歌曲播放、模式预览和聆听统计不改变歌单顺序。候选不足时显示真实可用数量，不伪造播放量或歌单。
- 每日推荐歌曲、每日→雷达封面队列仍使用原来的缓存和顺序；内部调用home不会触发歌单重抽。只改变歌单不能延长每日歌曲缓存的原始有效期。
- 继续过滤每日推荐、私人雷达、私人漫游、心动模式、相似歌曲和我喜欢的音乐等专属歌单，下方列表与上方五入口保持独立。
- `music-workspace.js`删除右侧说明节点及赋值代码，不只是视觉隐藏。

## 验证

- 38项内容/发现/随机池与工作区测试通过，包含3页上限、150条上限、去重、上一次避让、访问内稳定、仅显式主页刷新重新抽取、取消后不写入迟到结果、caption节点彻底移除。
- `node scripts/check-music-recommendations.cjs`：7项真实匿名接口检查通过，读取三页后首次与第二次各18个，第二次18个全部不同；访问内顺序及每日歌曲保持一致。只读公开元数据，不读取本人Cookie、不下载音频。
- 成品账号检查`check-music-auth.cjs`增加主页访问稳定/下一访问重抽/每日歌曲不变三项，最终由发布流程对app.asar复核。

随机性作用于真实热门池；没有承诺每次抽取覆盖整个网易云曲库。网络失败时保留经筛选的真实推荐作为有限回退，不以错误字符串或固定假歌单替代。
