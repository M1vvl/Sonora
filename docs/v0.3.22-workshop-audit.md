## 确定问题与修复

1. 内置协议给所有文件附加 `frame-src 'none'`，而 Workshop 外壳必须嵌入原版桥接 iframe。这条 CSP 会阻止内层场景启动。现在仅 `workshop.html` 允许精确路径 `pulse-visual-media://builtin/sonic-workshop/mineradio-bridge.html`，其他内置文档及用户导入网页仍禁止嵌套 iframe。
2. 内层沙箱保留 `allow-scripts`，不加入 `allow-same-origin`。真实资源请求合同验证：相对路径解析到随包 ESM/CSS，JS MIME 为 `text/javascript`，CORS 为 `*`，支持 HEAD，保持 `nosniff` 与路径边界。
3. 原有外壳在 iframe/脚本加载时直接报告成功，无法证明场景存在。现在 `pulse-preset-ready` 只表示宿主可接收状态；`pulse-preset-presented` 需要原模块调用 `wallpaperReady`、有效视口上的默认 framebuffer 实际完成一次非零绘制、外层完成前景绘制三项全部满足。离屏预处理、空画布、空实例、外来消息均不能触发呈现。
4. 旧的 650ms 暂停宽限可能在冷启动的 ESM 完成前停住 RAF。现在启动阶段必须先完成首次真实绘制，再遵循暂停/不可见状态。恢复播放会接续已停放的回调，减少动效时按 10fps 更新而不会冻结播放时钟。
5. 原模块加载错误发送明确错误消息，由父渲染器保留上一张有效画面；可选封面图片失败不会误判为整个引擎失败。dispose 会取消 RAF、状态队列、桥接属性重试和主题过渡。
